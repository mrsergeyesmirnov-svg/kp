# KP — Telegram-бот для коммерческих предложений

Закрытый пилот для небольших маркетинговых агентств: профиль агентства + текст,
скриншоты переписки или аудио → черновик → правки → цена → подтверждение → PDF.
Сопроводительное письмо выдаётся отдельно. Бот ничего не отправляет клиентам.

## Запуск без установки Python на компьютер

1. Создать бота через @BotFather и получить BOT_TOKEN.
2. Подключить этот репозиторий к Docker-хостингу (например, Railway).
3. Добавить постоянный том, смонтированный в /data. Только одна реплика.
4. Заполнить переменные из .env.example в настройках сервиса:
   BOT_TOKEN, ALLOWED_USER_IDS (Telegram ID пилотных пользователей через запятую),
   AI_BASE_URL (HTTPS URL с /v1), AI_API_KEY, AI_MODEL.
   AI_AUDIO_MODEL нужен для аудио. Модель должна поддерживать изображения
   для скриншотов и JSON object для КП.
5. Запустить сервис. Dockerfile устанавливает шрифт с кириллицей.
6. Открыть бота, /start. Если раньше был настроен webhook — удалить его перед
   запуском polling через Telegram deleteWebhook.

Провайдер выбирается владельцем с учётом доступности его аккаунту и региону.
Код использует совместимые /chat/completions и /audio/transcriptions.
Токены не коммитить. .env автоматически не загружается: используйте переменные
хостинга или docker --env-file .env. В репозитории нет действующих ключей.

## Первый сценарий

Отправить одним сообщением:

    /profile Студия Пример
    Контакт: hello@example.com
    Услуги: лендинги, брендинг.
    Прайс: лендинг от 50 000 ₽.
    Кейсы: добавьте свои подтверждённые проекты.

Затем:

    /contact hello@example.com. Предоплата 50%, остаток после сдачи.
    /brand #2878B5
    /new
    Клиент — кофейня. Нужен лендинг с меню и формой заявки.
    /generate
    /edit Добавь этап согласования прототипа
    /price 50000
    /approve
    /pdf
    /email

Текст, фотографии и аудио добавляются в один бриф до /generate.
Добавление материалов сбрасывает старый черновик и цену, чтобы не экспортировать
неактуальное предложение. /edit сохраняет цену, но снимает утверждение.
/draft показывает сохранённый черновик после перезапуска.
/cancel очищает текущую сделку; /delete_me удаляет профиль и черновик из базы.

## Границы первой версии

- Один профиль и одна текущая сделка на Telegram-пользователя; данные разделены по ID.
- Один шаблон PDF с настраиваемым цветом; загрузки своего дизайна и логотипа пока нет.
- Итоговая цена задаётся вручную целым числом рублей; автоматических расчётов пакетов нет.
- Скриншоты — фото/JPEG/PNG, аудио — до 18 МБ. Поддержка конкретных аудиоформатов
  зависит от провайдера. PDF/Word на входе пока не поддерживаются.
- До 10 ИИ-запросов на пользователя в сутки UTC (DAILY_LIMIT).
  Распознавание каждого файла, генерация и правки расходуют запросы.
  Неуспешные попытки тоже учитываются. Удаление профиля сбрасывает счётчик:
  это ограничитель закрытого пилота, не биллинг.
- Последовательная обработка: длинная запись задерживает остальные запросы.
- SQLite требует постоянного тома и резервных копий. Профили, извлечённый текст
  и черновики хранятся до удаления; оригиналы медиа не сохраняются на диск.
- Возможна повторная обработка после аварии между ответом и записью offset.
- ИИ может ошибаться, включая цены в тексте: перед /approve необходима проверка.
- Нет платежей, подписок, CRM, истории версий, публичных ссылок и массовой рассылки.
- Перед запуском на внешних клиентах настройте свои условия обработки данных
  и провайдера. Сообщения Telegram и данные у провайдера удаляются отдельно.

## Проверка

    pip install -r requirements.txt
    python -m unittest -v

Тесты без ключей: изоляция пользователей, сохранение после перезапуска,
запрет PDF до утверждения, сброс утверждения при правках, валидация цены,
лимит запросов, PDF с кириллицей. Реальный Telegram/ИИ требуют переменных.

## Контекст и продажи

См. PROJECT_CONTEXT.md. Таблица agency_contacts.xlsx хранится отдельно от
публичного кода: в ней 15 контактов агентств и личные статусы работы с ними.
Контакты не импортируются в бот и не получают сообщений автоматически.
